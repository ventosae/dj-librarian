# W-25 plan: Spotify for any DJ (R-801 ... R-805, C-06)

Written 2026-10-20 before the build, checked against the CLAUDE.md hard rules.

1. **Audit (R-804).** `docs/spotify-audit.md`: one row per endpoint and field the code uses, status ok / fixed / removed / degraded, evidence `file:line`. No network: the reference is C-06 and `docs/lessons.md`. Fixes: `dj analyze` stops calling the removed batch `GET /artists?ids=` (`Spotify.artists` goes); `dj pull` of a playlist the app may not read (403/404: other users' or Spotify's playlists) ends in a plain error that names the fix (a 404 names both causes: gone/mistyped or not readable), and `dj analyze` skips 403 and 404 alike (one helper, `spotify.refused_status`); `pull_spotify.py` refuses `next` links off `api.spotify.com` (rule 6); a missing `popularity` no longer averages as 0 in `dj analyze`. Tests use `httpx.MockTransport`.
2. **Per-DJ links (R-802).** `intake.default_paths()`: when `libfolder.configured_root()/links.yaml` holds at least one entry, `Paths(<library>, library=True)`; otherwise `Paths()` = the repo root, exactly as today. `pull`, `match`, `plan`, `apply`, `status` use it. Library layout:
   - Visible, library-relative: `links.yaml`, `plans/<date>-<crate>.plan.json`, `wishlist/<crate>.md`, `wishlist/<crate>.shopping.md`, `reports/apply/<date>-<crate>.report.json` (names the plan library-relative).
   - Machine state under `.cache/` (gitignored by the scaffold): `.cache/inbox/`, `.cache/state/` (match_cache, declined). Until the library has its own, the repo's `state/` files are read (never written); the first apply copies them over. `dj status` lists them (`state_from_repo`).
   - A plan lists local file paths (candidates): each plan appends `plans/*.plan.json` to the library `.gitignore` (append-only) and creates `plans/.gitignore` if missing. Deviation from contract section 0 (absolute paths only in exports/proposals XML): plans keep them, gitignored, so R-905 holds.
   - MCP `dj_apply_preview`, `dj_apply_write`, `dj_build_*` take their file through `library_file()` (library folder or repo; an unusable library setting leaves the repo, like the CLI).
3. **Shopping list (R-803).** Door-1 core `dj.shopping` (stdlib + `dj.libfolder`): rows = the MISSING items of the newest plan for the link (the last match written down; slug matched case-insensitively; a pull newer than the plan sets `stale_plan` and one summary line), artist/title/label from the pulled inbox. `dj wishlist shop <link> [--json]` (`src/dj/commands/wishlist.py`, one `add_typer` line) rewrites `wishlist/<crate>.shopping.md` (temp + `os.replace`; a generated report, its header says so) and appends a `log.md` line when a library folder is in use. Beatport and Bandcamp search links are built, never fetched. BPM and key are `-` (no audio features for new apps). MCP `dj_wishlist_shop(link)`, `readOnlyHint=False, destructiveHint=False`.
4. **Guided setup (R-801, R-805).** `plugin/skills/dj-spotify/SKILL.md`: the Y1 card (Premium, own app, redirect URI, `.env`, proof = first `dj pull`), C-06 limits, scopes, shopping list, push/build for any DJ. `dj-sync`: one sentence on where links.yaml lives.

Hard rules:

- (1) Spotify: only `POST /me/playlists` (private) and `POST /playlists/{id}/items`; nothing removed or reordered. pull, match, plan and shop never touch rekordbox.
- (2) push, build and apply stay dry-run without `--apply`; shop writes one derived text file and nothing else.
- (6) `.env` stays in the repo root (the engine's folder), not in the library folder Claude reads in Cowork. The skill never asks for keys in chat and never prints `.env`. The bearer token goes only to `https://api.spotify.com/v1/` (existing test kept); client id, secret and refresh token go only to `accounts.spotify.com/api/token` (OAuth).
- (7) Synthetic data only; links stay in `examples/` and the DJ's own folder.
- Tests prove: search limit 10, `/items` rows with `item`, no removed endpoint in any flow, the loop with an empty repo, the shopping list offline, build/push dry-runs with a tmp `.env`.

Deviations from the v0.1 contract (for the W-25 paragraph in `docs/plan.md`; the integrator writes it):

- Plans in a library folder keep absolute local paths (candidate `path`); contract section 0 allows them only in exports/proposals XML. Kept out of git: `plans/*.plan.json` in the library `.gitignore` (append-only, `libfolder.ensure_gitignore(root, extra)`) plus `plans/.gitignore`.
- Library layout of the inbox loop as above (`.cache/` for inbox and state; `reports/apply/` for apply reports); the repo `state/` is read until the first library apply. `dj pull`/`plan`/`apply` write no `log.md` line yet (R-904 is W-22's); `dj wishlist shop` does.
- The shopping list reads the newest plan, not a stored match (`dj match` writes nothing); a newer pull is flagged `stale_plan`. It writes a derived text file, so no `dj.gate` preview id (text-file writer like `dj_plan`).
- MCP plan/tracklist tools moved from `repo_file()` to `library_file()`; `library_file()` falls back to the repo when the library setting is unusable (this also applies to `dj_library_inspect`).
