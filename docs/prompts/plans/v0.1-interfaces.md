# v0.1 interfaces — the contract every work item builds against

Written 2026-10-20 before W-11. Each work item implements its part exactly as named here so the
items fit together. If an item must deviate, it says so in its own section of `docs/plan.md`.
Hard rules in `CLAUDE.md` win over anything here.

## 0. Conventions (all items)

- **Door-1 core is stdlib + PyYAML only.** These modules must import without pyrekordbox, rapidfuzz,
  httpx, typer or mcp, because skill scripts run them in Cowork's sandbox (Q-06):
  `dj.model`, `dj.readers.common`, `dj.readers.xml`, `dj.libfolder`, `dj.treeschema`,
  `dj.analysis.*`, `dj.taste_files`, `dj.report`, `dj.writers.rekordbox_xml`, `dj.gate`,
  `dj.build_structure`, `dj.crate`, `dj.barber`. `tests/test_door1_imports.py` (W-11, extended by
  later items) imports each in a subprocess with those packages blocked. Do not import `dj.match`,
  `dj.library` or `dj.rules` from them (they pull rapidfuzz / pyrekordbox).
- **Deterministic.** No randomness, no wall clock inside logic. Functions that need a date take
  `today: date | None = None`; tests pass a fixed date. Sorts have explicit tie-breakers (track id).
- **Library-relative paths.** Every file written into a `dj-library/` folder refers to other files by
  POSIX path relative to that folder. Absolute paths appear only in `exports/*.xml` and
  `proposals/*.xml` (machine data, gitignored by the scaffold's `.gitignore`).
- **Measured vs words (R-302).** Every generated MD file starts with `# <Title>` and then one
  provenance line: `> Measured by code: <module> from <relative source file>, <YYYY-MM-DD>.`
  Sections written by Claude carry `> Words by Claude, from <relative files>.` Numbers in MD come
  from code; Claude never invents a number.
- **Lists ≤ 5** in every DJ-facing MD section, the HTML report and chat (R-1002 rule 9). Full data
  goes into JSON sidecars.
- **Writers.** Dry-run by default. A real write needs `apply=True` **and** a valid `preview_id`
  from `dj.gate` (R-1102). Files are written to a temp file then `os.replace`. Every writing command
  appends one line to `log.md` through `dj.libfolder.append_log` (R-904).
- **Skills.** `plugin/skills/<name>/SKILL.md` (+ `scripts/`). Frontmatter `name` = folder name and a
  `description`. Body names its R-ids, references `../../shared/voice.md` and
  `../../shared/adhd.md`, and ends with the section `## Pre-send checklist` copied from
  `plugin/shared/adhd.md`. Scripts are thin: argument parsing + a call into `dj.*`; they start with
  the import shim:

  ```python
  try:
      import dj  # noqa: F401  (engine venv, or a future PyPI install)
  except ImportError:  # plugin inside a clone of the repo
      sys.path.insert(0, str(Path(__file__).resolve().parents[4] / "src"))
  ```

  Every script prints one JSON object on stdout and exits 0 / 1 (error) / 2 (refused).
- **CLI.** New commands live in new modules registered in `cli.py` with one `app.add_typer(...)` line
  each. `dj library ...` lives in `src/dj/commands/library.py` (created by W-11, later items add
  subcommands there). `dj wishlist ...` (W-25) gets its own module.
  Existing commands keep their behaviour except where an R-id says otherwise (R-205, NFR-03, NFR-05).
- **MCP.** Tools are appended to `mcp_server.py`. Read tools: `READ` annotation. Tools that write
  only text files in the library folder or repo: `ToolAnnotations(readOnlyHint=False,
  destructiveHint=False)`. Writes: `WRITE`. Path arguments go through `library_file()` (W-11):
  must resolve inside the repo or inside the configured library folder.
- **Tests.** `tests/xml_fixtures.py` (W-11) is the one synthetic library everybody uses. No real
  data, no network, no real master.db; files only under `tmp_path`.

## 1. Model and readers (W-11)

`dj/model.py` — frozen dataclasses, no pyrekordbox:

- `LibraryError(ValueError)`.
- `Track`: `id: str`, `artist`, `title`, `album`, `duration_s: int`, `isrc`, `bitrate: int`,
  `location: str` (POSIX path, decoded), `kind` (`mp3|m4a|flac|wav|aiff|unknown`), `bit_depth: int`,
  `sample_rate: int`, `file_size: int`, `bpm: float` (real BPM), `key`, `genre`, `label`, `remixer`,
  `year: int`, `rating: int` (0–5 stars), `colour: str`, `comment`, `date_added: date | None`,
  `play_count: int`, `my_tags: tuple[str, ...]`, `cue_count: int`, `has_artwork: bool`. All defaults
  safe (`""`, `0`, `None`, `()`, `False`). Property `label_line` = `"Artist - Title"`.
- `PlaylistNode`: `id: str`, `kind` (`folder|playlist|smart`), `name`, `children: tuple`,
  `track_ids: tuple[str, ...]` (order kept), `rules: tuple[dict, ...]` (smart only, raw form),
  `path: tuple[str, ...]` (filled by the builder). Property `path_str` = `"/".join(path)`.
- `Library`: `source` (`xml|db`), `source_path: str`, `rekordbox_version: str | None`,
  `read_at: str` (ISO), `tracks: dict[str, Track]`, `roots: tuple[PlaylistNode, ...]`.
  Methods: `walk()` (every node, depth-first, tree order), `playlists()` (playlist + smart, flat),
  `folders()`, `node_at(path: str | tuple)`, `tracks_in(path)` (Track list, playlist order, unknown
  ids skipped), `orphans()` (tracks in no playlist or smart playlist, sorted by id),
  `counts()` → `{"tracks", "folders", "playlists", "smart", "orphans", "entries"}`.
- `dj/readers/common.py`: `kind_from(kind_text, location)`, `posix_location(url_or_path)` (decodes
  `file://localhost/` URLs, percent-escapes, backslashes), `parse_date(text) -> date | None`,
  `stars_from_rating(raw)` (0/51/…/255 → 0–5), `BPM_SCALE = 100` (equal to `dj.rules.BPM_SCALE`,
  asserted by a test, not imported).
- `dj/readers/xml.py`: `read_xml(path, *, read_at=None) -> Library` with `xml.etree.ElementTree`
  (stdlib, Door 1). Attribute names as in `pyrekordbox.rbxml.Track.ATTRIBS`; a test cross-checks the
  fixture against `pyrekordbox.rbxml.RekordboxXml`. `XML_FIELDS_MISSING` = the model fields the
  export does not carry. The `ROOT` node is not a root of the Library; its children are.
- `dj/readers/db.py`: `read_db(master_db=None) -> Library`, snapshot copy only (R-202).
- `dj.mcp_server.library_file(path, suffixes)`: like `repo_file`, but also accepts paths inside the
  configured library folder (`dj.libfolder.configured_root()`).
- CLI `dj library inspect [XML] [--json]`; MCP `dj_library_inspect(xml: str = "")`.

## 2. Library folder and tree schema (W-12)

`dj/libfolder.py`:

- `SCHEMA_VERSION = 1`; `DIRS = ("exports", "profile", "structure", "taste", "crates", "reports",
  "proposals", "wishlist")`; files `README.md`, `library.yaml`, `links.yaml`, `log.md`, `.gitignore`.
- `LibraryFolder(root: Path)` frozen; properties for each dir/file, plus `cache` = `root/.cache`.
- `scaffold(root, *, device, rekordbox_version=None, today=None) -> ScaffoldResult(created, skipped)`:
  create-only; an existing file is never overwritten (SKIP). `device` is `mac|windows`.
- `library.yaml` keys (R-902): `schema_version`, `device`, `rekordbox_version`, `created`, `updated`,
  `structure: {chosen: null}`, `exports: {latest: null}`. `load_meta(root) -> dict`,
  `validate_meta(data) -> list[str]` (errors), `update_meta(root, today=None, **changes)`.
- `import_export(root, xml_path, *, today=None) -> Path`: **copies** (never moves) the DJ's XML to
  `exports/<YYYY-MM-DD>-collection.xml` (`-2`, `-3` … if taken; identical content → SKIP), records
  `exports.latest` and the XML's PRODUCT version in `library.yaml`.
- `latest_export(root) -> Path` (from `library.yaml`, else newest `exports/*.xml`).
- `append_log(root, action, counts=None, file=None, now=None) -> str`: appends
  `YYYY-MM-DD HH:MM <action> -> <n> <key>, <n> <key>; <file>` to `log.md` and returns the line.
- `configured_root() -> Path`: `DJ_LIBRARY` env, else the path stored in `state/library-path.txt`
  (repo, gitignored), else `REPO_ROOT / "dj-library"`. `remember_root(path)` writes that file.
- `relative(root, path) -> str` (POSIX; raises `LibraryError` outside the folder).
- Scaffold `.gitignore`: `exports/*.xml`, `proposals/*.xml`, `.cache/`, `.env`.

`dj/treeschema.py` — one loader for `bases.yaml`, `structure/current-tree.yaml` and `proposals/*.yaml`
(R-903):

- `TreeNode(kind, name, children=(), rules=None, rules_raw=None, fill_from=())` frozen.
  YAML keys: exactly one of `playlist|folder|smart`; folder → `children`; smart → `rules` (v1 rule
  list, shape-checked against `RULE_TYPES`, a tuple equal to `dj.rules.RULE_TYPES` keys — asserted by
  a test) or `rules_raw` (a string, for rules v1 cannot express); playlist → `from` (list of existing
  playlist paths `"A/B"` whose tracks pre-fill it, R-503). Unknown keys and duplicate names at one
  level are errors (`TreeSchemaError(ValueError)`, defined in `treeschema`).
- `TreeDoc(nodes: tuple[TreeNode, ...], meta: dict)`. A file is either a bare list (bases shape) or a
  mapping `{tree: [...], name?, family?, principle?, source?, generated?}`.
- `parse(data, where) -> TreeDoc`, `load(path)`, `dumps(doc) -> str`, `dump(doc, path)`.
  Guarantee: `parse(yaml.safe_load(dumps(doc))) == doc`.
- `walk(doc)` → `(path tuple, TreeNode)` depth-first. `to_tree_nodes(doc) -> list[dj.tree.Node]`
  (imports `dj.tree` lazily; smart without v1 rules → `TreeSchemaError`).
- `diff(proposal, current) -> list[DiffRow(op, kind, path, fill_from, note)]`, op in
  `CREATE | SKIP | CONFLICT | MANUAL` (MANUAL = smart node, XML cannot carry rules).
- `bases.example.yaml` and `tree.example.yaml` parse to the same names/kinds through both
  `treeschema.load` and `dj.tree.load_tree` (test).

## 3. Onboarding and shared voice (W-13, W-19)

- `plugin/skills/dj-start/SKILL.md` + `scripts/start.py`:
  `start.py init --library DIR --device mac|windows [--xml FILE]` → scaffold + `import_export` +
  `{"created", "skipped", "export", "counts"}`; `start.py find-xml --library DIR` → newest `*.xml`
  outside `exports/` and `proposals/`. P4 runs, in order: dj-profile, dj-structure, dj-taste,
  dj-report scripts. The M1 engine card is `plugin/skills/dj-start/engine.md` (W-21).
- `plugin/shared/voice.md` (≥ 5 do/don't pairs, our own words, C-08) and `plugin/shared/adhd.md`
  (the 10 rules with attribution, C-09, and the canonical `## Pre-send checklist`).
  `tests/test_skills.py` (W-19) checks every skill folder, including that its last section is this
  block, character for character (it is also the last section of `plugin/shared/adhd.md`):

```markdown
## Pre-send checklist

Before every reply, check:

- [ ] The first line is the next action or the answer. No preamble, no pleasantries.
- [ ] Where we are is restated in one line (for example "Step 2 of 6").
- [ ] Steps are numbered, with one concrete time estimate.
- [ ] Lists have 5 items or fewer.
- [ ] No tangents: only what this step needs.
- [ ] Finished work is visible: name the file that was written.
- [ ] Errors are stated matter-of-fact: what failed, what happens next.
- [ ] It ends with one action that takes under 2 minutes.
- [ ] Voice: a working DJ talking to a DJ. Blunt, practical, no hype (shared/voice.md).
- [ ] Nothing was written to rekordbox, Spotify or audio files without a preview and an explicit yes.
```

## 4. Analysis (W-14, W-15, W-16)

All in `dj/analysis/`: `common.py` (norm key for duplicates without rapidfuzz, token helpers),
`profile.py`, `structure.py`, `taste.py`. Each has `facts(lib, *, today=None) -> dict` (pure,
JSON-serialisable) and `write(folder: LibraryFolder, facts, *, source: str, today=None) -> list[Path]`.
`run(folder, *, xml=None, today=None) -> dict` reads `latest_export` (or `xml`), computes, writes,
appends a log line, and returns `{"written": [...relative paths], ...summary}`.

- **profile** (R-311): writes `profile/stats.md`, `profile/facts.json`. Facts keys: `size`
  (tracks, hours, gb), `formats`, `bitrates` (buckets `<192`, `192-255`, `256-319`, `320`,
  `lossless`, `unknown`), `eras` (decades), `timeline` (per year, first/last added, busiest month),
  `fields` (share filled per field: genre, bpm, key, rating, colour, comment, label, my_tags),
  `empty` (counts), `duplicates` (groups count + top 5), `headline` (exactly 5
  `{label, value, note}` for the report, R-402). `profile/habits.md` is Claude's (R-312); the script
  never writes it.
- **structure** (R-321, R-322): writes `structure/analysis.md`, `structure/graph.json`
  (`nodes`, `edges`, `overlaps`), `structure/facts.json`, `structure/current-tree.yaml`
  (`treeschema.from_library(lib)` added in W-15; round-trips). Facts: `depth`, `width`, `naming`,
  `sizes`, `overlap` (Jaccard pairs ≥ 0.5, top 5), `orphans`, `empty`, `dumps`, `smart_vs_plain`,
  `reveals` (≤ 5 short strings).
- **taste** (R-331, R-332): writes `taste/lanes.md`, `taste/labels-artists.md`, `taste/anchors.md`,
  `taste/vocabulary.md`, `taste/facts.json`, `taste/cooccurrence.json`. Facts: `labels`, `artists`,
  `lanes` (per playlist BPM median and range → lane), `keys`, `cooccurrence` (pairs in ≥ 2
  playlists), `top_rated`, `most_played`, `anchors` (1–3 per cluster), `vocabulary` (tokens from
  playlist and folder names, counts).
- `dj/taste_files.py` (W-16): entry files are Markdown lists of
  `- [YYYY-MM-DD] <text> <!-- key:<stable key> -->`. `append_entries(path, title, entries,
  today) -> list[str]` keeps every existing line verbatim, appends new keys, appends an
  `updated:` entry when a key's text changed; never rewrites (R-332). A full rebuild needs
  `rebuild=True`, which the scripts only pass with `--rebuild`. Parsers: `read_entries(path)`,
  `read_vetoes(path) -> Vetoes(never_propose: frozenset[str], never_pair: frozenset[frozenset[str]])`
  from lines `never propose: <label> <!-- key:veto:<id> -->` and
  `never pair: <a> + <b> <!-- key:pair:<id1>,<id2> -->`; `read_feedback(path)`.

## 5. Report and proposals (W-17)

- `dj/analysis/proposals.py`: `candidates(lib, profile, structure, taste) -> list[Proposal]`, 2–3
  items, families `bases | facets | gig-first` (R-405; picking rules in the module docstring and in
  `dj-report/SKILL.md`). `Proposal`: `slug`, `name`, `family`, `principle` (one line), `tree`
  (`TreeDoc`, playlists carry `from`), `lands` (≤ 5 shown, full list in data: `{from, to}`),
  `cost_minutes: int` (formula in the docstring), `trigger` = `"Build me the <name> structure"`.
  Written to `structure/proposals.yaml` (list of mappings with a `tree:` key each).
- `dj/report.py`: `render(folder, *, today=None) -> Path` → `reports/<YYYY-MM-DD>-library.html`.
  Self-contained (inline CSS and SVG, no `<script src>`, no `http(s)://`). Sections
  `id="who"` (narrative from `profile/habits.md` or a placeholder + exactly 5 stats),
  `id="structure"` (SVG tree + overlap, reveals ≤ 5), `id="proposals"` (2–3, each with
  `data-part` = `name, principle, tree, lands, cost, trigger`), `id="next"` (one action < 2 min).
- CLI `dj library report`; MCP `dj_library_analyze(source: str = "xml")` runs profile, structure,
  taste, proposals and report.

## 6. Build, gate, crates, barber (W-18, W-21, W-23, W-24)

- `dj/gate.py` (W-18): `Gate(state_dir)`; `record(kind, args: dict, digest: str) -> preview_id`
  (`sha256(kind, args, digest)[:12]`), stored as `<state_dir>/previews/<id>.json`;
  `check(preview_id, kind, args, digest)` raises `GateError` when missing, for another kind/args,
  changed since the preview, or already used; `consume(preview_id)` after a successful write.
  Library-folder state dir = `<library>/.cache`; repo state dir = `REPO_ROOT/state`.
- `dj/writers/rekordbox_xml.py` (W-18): `build_xml(doc, lib, *, only=None) -> str` (stdlib
  ElementTree; `DJ_PLAYLISTS Version="1.0.0"`, `PRODUCT Name="dj-librarian"`, `COLLECTION` with only
  the referenced tracks, original `TrackID` and `Location` re-encoded as `file://localhost/...`,
  `PLAYLISTS/NODE Name="ROOT"`; folders `Type="0" Count`; playlists `Type="1" KeyType="0"
  Entries`, `TRACK Key=<TrackID>`). `write_xml(text, path)` atomic. pyrekordbox's `RekordboxXml`
  must read the output back with the same playlists (test).
- `dj/build_structure.py` (W-18): `preview(folder, proposal) -> BuildPreview(rows, digest,
  preview_id, yaml_path)` writes `proposals/<slug>.yaml` and records a preview;
  `apply(folder, proposal, preview_id) -> BuildResult(xml_path, import_steps, log_line)`.
  The XML holds the CREATE nodes and their ancestor folders. Never opens master.db (R-504).
  CLI `dj library build <proposal> [--apply --preview-id ID]`; MCP `dj_structure_preview(proposal)`
  and `dj_structure_write(proposal, preview_id)`.
- W-21: every existing write tool gains a required `preview_id`; preview tools return one. DB writes
  need `--power-mode` and Windows (R-205). PreToolUse hook `plugin/hooks/hooks.json` +
  `plugin/hooks/gate.py` denies write tools without `preview_id` (Claude Code only, C-10).
- `dj/crate.py` (W-23): `CrateSpec` from `crates/<slug>.spec.yaml` (`name`, `size` in 30/50/70,
  `brief`, optional `bpm: [lo, hi]`, `keys`, `lanes`, `genres`, `exclude_genres`, `anchors`,
  `my_tags`, `min_rating`, `curve: flat|warmup|peak`). `select(lib, spec, taste_facts, vetoes)
  -> CrateResult(picks, spares)`: exactly `size` picks, `ceil(0.2 * size)` spares spread over energy
  tiers, a one-line factual reason per track, vetoes honoured, same spec → same result.
  Writes `proposals/crate-<slug>.xml` + `crates/<slug>.md` behind the gate. CLI
  `dj library crate <spec> [--apply --preview-id]`; MCP `dj_crate_preview`, `dj_crate_write`.
- `dj/barber.py` (W-24): `plan_session(lib, taste, today) -> Session` (≤ 8 questions),
  `question(session, n)`, `record(folder, session, n, answer, today) -> list[str]` appends dated
  entries to `taste/*.md` through `taste_files`. Session state in `<library>/.cache/barber.json`.
  CLI `dj library barber next|record`; MCP `dj_barber_next`, `dj_barber_record`.
