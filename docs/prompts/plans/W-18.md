# W-18 dj-build: design, checked against the CLAUDE.md hard rules

R-501..R-505, R-904, R-1102. Contract 5, 6. `find_proposal` (slug, name or trigger; the DJ's
`proposals/<slug>.yaml` first) -> `preview` -> the DJ says yes -> `apply(preview_id)`.

- `dj.gate` (Door 1): `Gate(state_dir)`, records `<state_dir>/previews/<id>.json`; id =
  sha256(kind, canonical args, digest)[:12]. `check` refuses missing, other kind/args, used,
  older than 24 h (UTC), digest changed. `consume` marks it used; a used id stays used.
- `dj.writers.rekordbox_xml` (Door 1): `build_xml(doc, lib, only=, product_version=)` -> text;
  `write_xml(text, path)` create-only (`<slug>-2.xml`, `-3` ...; never replaces a file).
- `dj.build_structure` (Door 1): latest export (`read_xml`) + `structure/current-tree.yaml`;
  `treeschema.diff` -> CREATE / SKIP / CONFLICT / MANUAL, checked against the export's own tree
  (they differ -> blocked: run dj-structure). Digest = proposal YAML + current tree YAML + export
  (path, tree) + the track ids of every playlist the XML will hold.

Hard rules, line by line:
1. Create and add only: `proposals/<slug>.yaml` (create-only; the DJ's edits win), `.xml`
   (create-only, numbered when taken), the gate record in `.cache/`, one appended `log.md` line,
   `structure.chosen`. Nothing in rekordbox, Spotify or on disk is renamed, moved or removed.
2. Dry-run default: `preview` writes no XML. `apply` needs a gate preview id; the CLI refuses
   `--apply` without `--preview-id` before reading anything; the MCP write tool refuses an empty
   id without running. The skill asks "Write the XML?" and takes only an explicit yes.
3. master.db is never opened: Door-1 modules only (`read_xml`, never `dj.safety.open_db`); a
   test runs preview + apply with pyrekordbox blocked and `open_db`/`_connect` raising (R-504).
4. XML is the write path: the DJ imports `proposals/<slug>.xml` by hand (import card per OS).
5. Idempotent: an existing node (case-insensitive) is SKIP, stays out of the XML and keeps its
   rekordbox spelling; a CONFLICT, zero CREATE rows, a stale current tree or a build already
   written for this content blocks the build (no preview id; `apply` refuses).
6. Secrets: none read or printed. 7. Nothing personal: synthetic files in tmp_path; absolute
   paths only in `proposals/*.xml` (gitignored). 8. Smart playlists: MANUAL, left out of the XML.
