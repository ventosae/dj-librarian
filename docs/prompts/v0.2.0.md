The owner's calls of 27 Nov: one write path on every OS, XML deleted, 7 skills, a track catalog, playlists at two speeds. One PR, five commits in this order, each green on its own.

## Commit 1 — direct write on every OS
- Remove the OS check (`safety.DB_WRITE_PLATFORMS`, `write_gate.require_power_mode`) and the power-mode requirement. `mode="db"` is the default on Windows and Mac. `DJ_POWER_MODE=false` is the only off switch; install stops writing it.
- The chain, nothing else: preview id (one preview, one write) → rekordbox not running (`rekordbox` on Mac, `rekordbox.exe` on Windows; if the check cannot run, refuse) → verified backup → one transaction, rollback on failure.
- Tests, fake db, Mac and Windows paths: it writes; rollback leaves the db byte-identical; refuses while rekordbox runs; refuses a used preview id.

## Commit 3 — 7 skills, reply rules inline
- Names unchanged: `dj-start` (absorbs dj-profile, dj-structure, dj-taste, dj-identity, dj-report), `dj-crate`, `dj-build`, `dj-barber`, `dj-tidy`, `dj-spotify` (absorbs dj-sync), `install` (absorbs uninstall and backup). No aliases. Limits: 200 lines per SKILL.md, 300 for dj-start; rare detail in a file beside the skill.
- Write questions: "Close rekordbox first." then "Write it into rekordbox?" Yes / Change / Stop.
- Delete `plugin/shared/` and the pre-send checklist everywhere. Each SKILL.md starts with this block, verbatim:

  ## How to reply
  1. First line is the answer or the next move. No greeting, no recap, no sign-off.
  2. A working DJ talking to a DJ, first person: "I matched 41 of 48." Blunt, no hype. Booth words (crate, set, floor), never developer words.
  3. Say where we are in one line: "Step 2 of 4".
  4. Number the steps, one action each, with a real time: "about 2 minutes".
  5. One question per reply, with choices to tap.
  6. Lists stop at 5. The rest goes in a file; name the file.
  7. Every number comes from the tool. Not measured, not said.
  8. Taste is the DJ's call: versions, keepers, deletions. Offer, don't pick.
  9. Errors in one line: what failed, what happens next. No apology.
  10. End with one thing the DJ can do in under 2 minutes. Nothing is written to rekordbox, Spotify or audio files without a preview and a yes.

- One test: each of the 7 SKILL.md starts with the block and is under its limit.

## Commit 4 — catalog
- `src/dj/catalog.py`: from the master.db snapshot, write `<dj-library>/catalog/catalog.db` (plain SQLite) and `catalog/tracks.csv`. Tables: `tracks` (every `model.Track` field, plus Camelot code and local/streamed), `playlists`, `playlist_tracks` (in order), `notes` (track, field, value, source, date; survives every rebuild).
- Built by `dj_library_analyze` at setup; rebuilt when master.db's sha256 (the one `backup.py` computes) differs from the one stored in the catalog.
- Tools: `dj_query(sql, page)`: read-only connection, one SELECT only, 200 rows a page, counts first. `dj_note(track_id, field, value, source)`. dj-start says where the two files are, in one line.
- The DJ's catalog never enters the repo; tests build one from the fake db. Tests: row counts match; notes survive a rebuild; csv rows = tracks; `dj_query` refuses anything but a SELECT.

## Commit 5 — long playlists in dj-crate
- Fast, unchanged: "Crate me 50 for Saturday" → one question at most → preview → write.
- Long, when the DJ names a seed track or says "build it with me": up to 4 questions, one per reply, with choices: slot in the night · BPM window (her lanes as the choices) · a seed track · length, and "my tracks only / also what to buy".
- Seed: find it with `dj_query`; owned → it becomes an anchor and sets BPM, key neighbours and genre in the spec. Not owned → look it up on the web.
- Research: web search, 8 searches at most: scene and genre, label mates, who plays it, tracklists it is on. Output: "Artist - Title" candidates with links. No web search in the session → skip it and say so.
- New tool `dj_match_tracks(candidates)` (reuse `match.py` and `shopping.py`): owned ids, and the missing ones with store links. Spec gains `prefer` (owned candidates score up) and `exclude` (ids). The missing go to `crates/<slug>.to-buy.md`; sources go into the crate record.
- Preview: first 5 picks with a reason each, the counts, how many to buy. Then the write question. Edits by talking ("darker", "drop 7", "more like 3") change the spec and preview again.
- Tests: `dj_match_tracks` on the fake db; `prefer`, `exclude` and the seed anchor change the picks as stated.
