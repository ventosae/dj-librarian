Confirm each against the pyrekordbox source and record what the export does NOT carry (My Tags? history? smart-playlist rules?) in `docs/lessons.md` and as the answer to Q-01 in `docs/plan.md`.

## Task
Branch `feat/library-model-readers` off `main`. Conventional commit at the end: `feat: library model with XML and master.db readers`.

1. `src/dj/model.py` — frozen dataclasses, no pyrekordbox imports:
   - `Track`: `id`, `artist`, `title`, `album`, `duration_s`, `isrc`, `bitrate`, `location` (posix path), `kind` (mp3/m4a/flac/wav/aiff/unknown), `bit_depth`, `sample_rate`, `file_size`, `bpm` (float, real BPM), `key`, `genre`, `label`, `remixer`, `year`, `rating`, `colour`, `comment`, `date_added` (date | None), `play_count`, `my_tags` (tuple[str, ...]), `cue_count`, `has_artwork`. Every field default-safe.
   - `PlaylistNode`: `id`, `kind` (folder | playlist | smart), `name`, `children` (tuple), `track_ids` (tuple, in order), `rules` (tuple of dicts, smart only). Property `path` set by the parent on build.
   - `Library`: `source` ("xml" | "db"), `source_path`, `rekordbox_version`, `read_at`, `tracks` (dict id → Track), `roots` (tuple[PlaylistNode]). Methods: `playlists()` (flat, with paths), `tracks_in(path)`, `orphans()` (tracks in no playlist), `node_at(path)`, `counts()` → dict.
2. `src/dj/readers/__init__.py`, `src/dj/readers/xml.py`: `read_xml(path) -> Library`. Maps every field above that the export carries; missing fields stay default; `my_tags` empty with a module constant `XML_FIELDS_MISSING` listing what the export lacks. Location decoded from `file://localhost/...` to a posix path. Duplicate TrackIDs → `LibraryError`.
3. `src/dj/readers/db.py`: `read_db(master_db: Path | None = None) -> Library`. Copies `master.db` (+ `-wal`, `-shm`, `masterPlaylists6.xml` if present) to a temp dir and opens the COPY read-only through `safety`'s existing discovery and open path (R-202); never opens the live file; the temp dir is removed on exit. Builds `Track` from existing `library.to_track_info` output plus the fields it lacks (date added, play count, colour, My Tags) read through the pyrekordbox rows; builds the tree through `tree.children_of` / `tree.alive`, including smart playlists with their stored rules. Works with rekordbox open.
4. `src/dj/readers/common.py`: shared helpers (kind from extension, BPM scaling via `rules.BPM_SCALE`, posix location, date parsing).
5.
